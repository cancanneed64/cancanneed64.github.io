Kiro-Go 部署与 opencode 接入

09月02日, 2026年
阅读时长: 4 分钟

用 Docker 跑一个协议转换网关，让 opencode 能用上 Kiro 的模型池。记录部署过程和踩到的几个坑。 参考链接 项目地址

1. 它解决什么问题

Kiro 官方 API 不是公开的 OpenAI 格式，opencode 没法直接连。Kiro-Go 充当中间层，把标准格式的请求翻译成 Kiro 后端的私有协议，响应再翻译回来。

[opencode / curl / 任意 OpenAI 客户端]
        |  标准 HTTP 请求（OpenAI / Anthropic 格式）
        v
+------------------------------------------------+
|  Kiro-Go（Go 编写，宿主机 8081 端口）           |
|  |- 协议解析：区分 /v1/chat/completions        |
|  |             与 /v1/messages                 |
|  |- 账号池：多个 Kiro 账号凭证                  |
|  |- 路由：按剩余额度分配请求                    |
|  '- 凭证管理：OAuth token 自动刷新              |
+------------------------------------------------+
        |  转成 Kiro 内部协议（AWS 私有 API）
        v
[Kiro 后端]

几个关键机制：

  • 双向翻译：收到 {"model":"gpt-5.6-sol","messages":[...]}，重构成 Kiro 要的结构并补上私有签名头，拿到响应再打包回 OpenAI 格式。
  • 多账号轮询：每个账号一个额度池，按剩余额度和请求数选账号，避免单账号被限流。
  • Token 自动刷新：检测到 OAuth token 快过期就用 refresh token 换新的，不用手动重登。
  • Web 管理面板：加删账号、看额度、改密码，状态存在挂载出来的 data 目录里。

一句话：MCP 那种"能力"由后端提供，Kiro-Go 负责让任何 OpenAI 兼容客户端误以为自己在跟 OpenAI 说话。

2. 部署

镜像很小，32.6MB。

1
2
3
4
5
6
7

sudo docker run -d \
  --name kiro-go \
  --restart unless-stopped \
  -p 8081:8080 \
  -e ADMIN_PASSWORD='<你的密码>' \
  -v /home/bot/kiro-go/data:/app/data \
  ghcr.io/quorinex/kiro-go:latest

两个容易写错的地方：

  • 数据卷挂到 /app/data，不是 /data。挂错了账号配置不会持久化，重建容器就全丢。
  • 端口是 8081:8080：容器内监听 8080，宿主机映射到 8081。我这里 8080 被另一个 Node 服务占了（后面第 5 节说这事）。

验证：

1
2
3
4
5

# 模型列表
curl -s http://127.0.0.1:8081/v1/models | jq -r '.data[].id'

# 健康检查，期望 200
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8081/v1/models

管理面板在 http://127.0.0.1:8081/admin，密码就是启动时 ADMIN_PASSWORD 那个值。

密码想改的话，建议在面板里改。直接改环境变量得删容器重建，已添加的 Kiro 账号会一起没。

4. 模型名的点号

我最初手写了 13 个模型，结果 gpt-5.6-sol 在列表里找不到。查了才发现两个问题：

  1. 手写清单漏了一大半，网关实际提供 40 个模型。
  2. 已经写进去的名字有的还是错的——我写的 claude-opus-4-8，网关返回的是 claude-opus-4.8。中间是点号不是连字符。

模型 ID 必须和 /v1/models 返回值逐字符一致，包括点号和 -thinking 后缀。

所以别手写，直接生成。这条命令输出的 JSON 可以整块粘进 models 字段：

1
2

curl -s http://127.0.0.1:8081/v1/models \
  | jq '.data | map(.id) | unique | map({key: ., value: {}}) | from_entries'

改完顺手验证一下语法。当前配置文件虽然叫 .jsonc，但里面没有注释，所以可以直接用严格 JSON 校验（哪天加了注释这条就不适用了）：

1

python3 -m json.tool ~/.config/opencode/opencode.jsonc > /dev/null && echo "配置有效"

补齐后模型分几组：

组 模型
Claude opus-5 / sonnet-5 / opus-4.8 / opus-4.7 / opus-4.6 / sonnet-4.6 / opus-4.5 / sonnet-4.5 / sonnet-4 / haiku-4.5
GPT-5.6 sol / terra / luna
其他 deepseek-3.2、glm-5、qwen3-coder-next、minimax-m2.5、minimax-m2.1
旧版 gpt-4o、gpt-4
自动 auto、auto-thinking

除 gpt-4o / gpt-4 外，每个都有对应的 -thinking 版本。

5. 开机自启

--restart unless-stopped 会让 Docker 在宿主机重启后自动拉起容器。 一堆手动跑的开发服务重启后都得重新起，kiro-go 是少数配了自启的。

8. 安全注意

  • 面板密码别用默认值，/admin 拿到就等于能操作你所有 Kiro 账号。

  • 8081 默认监听 0.0.0.0，同网段任何设备都能直连。只在本机用的话应该绑到 127.0.0.1：-p 127.0.0.1:8081:8080。

  • 第三方中转站的 API key 如果明文写在 opencode.jsonc 里，注意文件权限。默认 644 是所有人可读，改成 600 更合适：

    1

    chmod 600 ~/.config/opencode/opencode.jsonc

  • 中转站声称的后端无法从客户端验证。响应里的 usage_source 之类的字段是它自己填的，理论上可以写任何值。要确认只能对用量账单。
